# Public release workflow

The GitHub Actions workflow Adventure Land HD Public Package produces a complete public distribution without modifying the official Adventure Land servers.

## Required input

asset_base_url must be the final public HTTPS directory that will contain the generated cdn/ tree.

Examples:

- https://assets.example.com/adventure-land-hd/v0.1.0
- https://cdn.example.net/alhd/mainland-2026-09

The browser packages generated by that run contain this URL permanently in page-manifest.js.

## Package-only mode

Leave publish_assets disabled.

The workflow still creates and verifies:

- Chromium MV3 ZIP;
- Firefox MV3 ZIP;
- static 48-image CDN tarball;
- build-info.json;
- cdn-manifest.json.

Upload the contents of the CDN tarball to the exact asset_base_url before distributing the extension packages.

## S3-compatible publish mode

Cloudflare R2 and Backblaze B2 can expose S3-compatible object APIs. To publish directly from GitHub Actions, configure these repository secrets:

- ALHD_S3_ENDPOINT
- ALHD_S3_BUCKET
- ALHD_S3_REGION
- ALHD_S3_ACCESS_KEY_ID
- ALHD_S3_SECRET_ACCESS_KEY

Then enable publish_assets and set asset_prefix to the object-key prefix corresponding to asset_base_url.

The workflow uploads only the generated PNG tree. It never uploads or executes remote JavaScript.

## CDN verification

Enable verify_public_cdn after the public URL is reachable.

The verifier samples the generated image inventory using an Origin header of https://adventure.land and requires:

- HTTP success;
- image/png Content-Type;
- Access-Control-Allow-Origin equal to * or https://adventure.land;
- exact expected byte length.

A failed CDN check blocks the workflow.

## Distribution

The Chromium and Firefox ZIPs can be used for store submission or testing/sideloading. They point at the same immutable image build and expose runtime state through ALHD.status().
